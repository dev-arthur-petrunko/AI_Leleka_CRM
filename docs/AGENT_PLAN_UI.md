## 0. Зачем эта фаза (что решили и почему)

Проверка текущего прототипа (скриншоты экранов) показала:

1. **Структура слабая для CRM «на все случаи».** Раздел «Угоди» спрятан в «Ще», хотя это ядро ежедневной работы. Вкладки «Замовлення» и «Вхідні» открываются пустыми.
2. **Нет каркаса, который есть в любой серьёзной CRM:** боковой панели на компьютере, верхней панели с глобальным поиском, кнопки «+ Створити», уведомлений, профиля, экрана «Сьогодні» для менеджера.
3. **Нет таблиц, фильтров, сохранённых видов, массовых действий, карточек с вкладками.**
4. **Цифры на экранах расходятся** (дашборд: 14 угод и 212 000 грн в работе; канбан: 6 угод и 103 700 грн).
5. **Служебные подписи разработчика видны пользователю** («дані: GET /analytics/dashboard», «у проді PATCH /deals/...», значок PREVIEW).
6. **Смесь языков и технических кодов** (`negotiation`, `hot`, `prom`, `form`).
7. **Слово «Замовлення» используется для двух разных вещей** (карточки угод названы «Замовлення #412»).
8. **Один тёмный вид и разрозненные шапки экранов, разные ширины колонок, разнобой иконок.**

### 0.1 Позиционирование (определяет приоритеты)

> **AI Leleka CRM: CRM для украинского интернет-магазина. Заказы с Prom и Rozetka, Нова Пошта, касса и оплата, Telegram и AI в одном месте. Настройка за 15 минут.**

Конкуренты, с которыми нас будут сравнивать: **KeyCRM, SalesDrive, Horoshop CRM** (украинские CRM для магазинов). С Zoho мы по ширине функций не конкурируем: наши преимущества это встроенные украинские интеграции, быстрый старт без интегратора, гривна, Telegram-first, поддержка на украинском. Всё, что не помогает этой формулировке, откладывается.

### 0.2 Не делать сейчас (чтобы не застрять)
- конструктор модулей и произвольных полей уровня Zoho (только простые кастомные поля: фаза 2.5 основного плана);
- маркетплейс расширений, публичный API-портал;
- мобильное нативное приложение (достаточно адаптивного веба и Telegram Mini App);
- конструктор отчётов (только фиксированные отчёты и фильтры).

## 1. Ключевые понятия (прочитать агенту до кода)

| Понятие | Что это | Аналогия |
|---|---|---|
| **Угода** (deal) | Продажа в процессе, до оформления: заявка с формы, переписка в Telegram, опт | Человек примеряет вещи в магазине |
| **Замовлення** (order) | Оформленный заказ: товары, оплата, доставка | Чек на кассе |
| Воронка (pipeline) | Набор стадий угоды | Дорога из пункта А в Б со станциями |
| **Дизайн-токен** | Именованное значение стиля (цвет, отступ) в одном файле | Палитра художника: все берут краску оттуда |
| Drawer (боковая панель) | Карточка объекта, выезжающая справа поверх списка | Выдвижной ящик |
| Command palette (командная палитра) | Окно по Ctrl+K: поиск и быстрые действия | Спотлайт на Mac |
| Optimistic update | Интерфейс меняется сразу, не дожидаясь сервера, и откатывается при ошибке | Вы нажали лайк, он горит сразу |
| Skeleton (скелетон) | Серый «каркас» экрана на время загрузки | Разметка стен до отделки |

**Главное правило связки:** угода при выигрыше превращается в замовлення; заказ с маркетплейса или сайта сразу создаётся как замовлення, и угода ему не нужна (опция «створювати угоду для кожного замовлення» выключена по умолчанию). Оба раздела главные и не дублируют друг друга.

## 3. Дизайн-система и темы «Ранок» и «Вечір»

### 3.1 Что такое темы
- **«Вечір»** — тёмная тема (текущий вид прототипа, стиль Telegram).
- **«Ранок»** — светлая тема.
- Режимы выбора: **Авто (за часом доби)**, **Ранок**, **Вечір**, **Як у системі**. Внутри Telegram по умолчанию **Як у Telegram**.

### 3.3 Как переключается тема
Логика в `frontend/src/theme/`:

```ts
type ThemeMode = "auto-time" | "morning" | "evening" | "system" | "telegram";

function resolveTheme(mode: ThemeMode, now = new Date(), tz = "Europe/Kyiv"): "morning" | "evening" {
  if (mode === "morning" || mode === "evening") return mode;
  if (mode === "system") return matchMedia("(prefers-color-scheme: dark)").matches ? "evening" : "morning";
  if (mode === "telegram") return window.Telegram?.WebApp?.colorScheme === "dark" ? "evening" : "morning";
  // auto-time: «Ранок» с 07:00 до 19:00, «Вечір» с 19:00 до 07:00 по часовому поясу пользователя
  const hour = Number(new Intl.DateTimeFormat("en-GB", { hour: "2-digit", hour12: false, timeZone: tz }).format(now));
  return hour >= 7 && hour < 19 ? "morning" : "evening";
}
```
Правила:
1. **Без «мигания» при загрузке:** в `index.html` до отрисовки (inline-скрипт в `<head>`) читается `localStorage["leleka.themeMode"]`, считается тема и ставится `document.documentElement.dataset.theme`.
2. Режим **сохраняется на сервере** (`users.preferences` JSONB: `theme_mode`, `theme_morning_from`, `theme_evening_from`, `timezone`) и подхватывается на любом устройстве; `localStorage` служит быстрым кэшем.
3. В режиме `auto-time` таймер пересчитывает тему при смене часа (проверка раз в минуту) и при возврате на вкладку (`visibilitychange`); границы 07:00 и 19:00 настраиваются в «Налаштування → Вигляд».
4. Внутри Telegram Mini App тема берётся из `Telegram.WebApp.colorScheme` и событий `themeChanged`; цвета берутся из наших токенов, а не напрямую из `themeParams` (чтобы вид был единым).
5. **Графики и всё, что рисуется скриптом** (Recharts, canvas), читают цвета из CSS-переменных и перерисовываются при смене темы.
6. Плавный переход цвета (150–200 мс), отключается при `prefers-reduced-motion`.
7. Переключатель темы в верхней панели: иконка солнца (Ранок) / луны (Вечір) + пункт меню «Авто». Подписи: **«Ранок»**, **«Вечір»**, **«Авто (за часом)»**, **«Як у системі»**.
8. Никаких цветов «в лоб» в компонентах: проверка линтером (`no-restricted-syntax` на hex-цвета в `src/**/*.tsx`), исключение только `tokens.css` и графические ресурсы.

### 3.4 Необязательное дополнение «Ранок/Вечір» в смысле ритма дня
Приветствие на «Сьогодні» зависит от времени: «Доброго ранку, <имя>» до 12:00, «Добрий день» до 18:00, «Добрий вечір» после. Опционально (флажок в настройках, по умолчанию выключено): **ранковий брифінг** в Telegram-бот в 09:00 (задачи на день, угоди без движения, новые заказы) и **вечірній підсумок** в 18:00 (что сделано, что осталось, выручка за день). Реализуется задачей Celery beat из фазы 3.1 основного плана; тексты через шаблоны, персональные данные клиентов в сообщения не включаются, только счётчики и номера заказов.

### 3.5 Проверки качества темы
- Скрипт `frontend/scripts/check-contrast.ts`: для пар `--text/--bg`, `--text/--bg-elevated`, `--text-muted/--bg-elevated`, `--primary-fg/--primary`, статусных цветов на фоне карточки считает контраст WCAG и падает, если обычный текст ниже 4.5:1 (крупный ниже 3:1). Запускается в CI.

### 4.4 Единый каркас страницы
Один контейнер: максимальная ширина контента 1440 px, поля 16/24/32 px по ширине экрана; у всех экранов одинаковая шапка (заголовок, действия справа); у списков одинаковая панель инструментов (поиск, фильтры, сохранённые виды, переключатель вида, экспорт). Ширины колонок «как получится» запрещены.

## 5. Экраны: подробные требования

Для каждого экрана обязательны **4 состояния**: загрузка (скелетон), данные, пусто (иконка, объяснение, **кнопка действия**), ошибка («Не вдалося завантажити» + «Повторити»). Все списки с пагинацией `{total, limit, offset, items}` и клавиатурной доступностью.

### 5.1 Головна («Сьогодні»)
Для менеджера (роль `manager`): приветствие по времени суток (3.4), 4 плитки (мої завдання на сьогодні, прострочені, нові замовлення, непрочитані повідомлення), блок **«Що зробити зараз»** — единый список, собранный бэкендом из: просроченных задач, угод без движения N дней, заказов, требующих действия (новые, неоплаченные, зависшие в доставке), непрочитанных диалогов; каждая строка ведёт на объект. Ниже «Мої угоди сьогодні». Для `owner/admin` вверху вкладки **«Мій день» | «Огляд бізнесу»** (второе — краткая аналитика).
Backend: `GET /today` (агрегат, учитывает `tenant_id` и пользователя).

### 5.2 Угоди (ядро)
- Переключатель **Канбан | Таблиця**, сохранённые виды: «Мої», «Усі», «Гарячі», «Прострочені», «Без руху 7+ днів» (свои виды можно сохранять).
- Фильтры: менеджер, источник, стадия, диапазон суммы, теги, дата создания.
- Канбан: заголовок колонки с количеством, суммой и **взвешенной суммой** (сумма × вероятность стадии); drag&drop (`dnd-kit`) с оптимистичным обновлением и отменой в течение 8 секунд (toast «Угоду переміщено · Скасувати»); кнопка «+ угода» в колонке; индикатор «без руху N дн» цветом **и иконкой с текстом**; на телефоне горизонтальная прокрутка с «примагничиванием» колонок.
- Карточка угоды открывается **боковой панелью (drawer)**, вкладки: Огляд, Листування, Завдання, Файли, Історія; сверху быстрые действия: «Подзвонити», «Написати в Telegram», «Створити завдання», «Створити замовлення».
- **Переход в «Виграно»:** диалог «Створити замовлення?» (позиции, сумма, доставка) → вызывает `POST /deals/{id}/convert-to-order`, связывает `deals.converted_order_id` и `orders.deal_id`. **Переход в «Програно»:** причина обязательна (список причин + «інше»).
- Названия карточек: **«Угода #412»** (или «Клієнт — товар»), а не «Замовлення #412».
- Подписи стадий через словарь: **Новий, Контакт, Переговори, Виграно, Програно** (стадии берутся из воронок, фаза 2.5 основного плана).
Backend: `GET /deals` (фильтры, пагинация, `view=kanban|table`), `PATCH /deals/{id}/stage`, `POST /deals/{id}/convert-to-order`, `GET/POST /views` (сохранённые виды: `saved_views` с `tenant_id`, `user_id`, `entity`, `filters` JSONB).

### 6.1 Единый демо-набор данных

Расхождение роняет CI.

## 7. Правила интерфейса (обязательные)

### 7.1 Ошибки и демо
`api()` возвращает `{ok, data, error}`; при ошибке экран показывает **баннер** «Немає звʼязку з сервером» и состояние ошибки с «Повторити». 401 → вход, 402 → экран тарифа, 403 → «Немає доступу». Молчаливого возврата выдуманных данных нет.

### 7.2 Словарь подписей (`frontend/src/i18n/uk.json`)
| Код | Подпись |
|---|---|
| `new` / `contacted` / `negotiation` / `won` / `lost` (стадии) | Новий / Контакт / Переговори / Виграно / Програно |
| `hot` / `warm` / `cold` | Гарячий / Теплий / Холодний (+ иконка) |
| сегменты `new/regular/vip/lost` | Новий / Постійний / VIP / Втрачений (позже RFM-названия) |
| `prom` / `rozetka` / `site` / `manual` / `form` | Prom / Rozetka / Сайт / Вручну / Форма |
| статусы заказа | Новий, Підтверджено, Зібрано, Відправлено, Доставлено, Скасовано, Повернено |
| оплата | Не оплачено, Оплачено, Частково, Повернено |
Любой код без записи в словаре виден в тесте как ошибка (скрипт ищет ключи без перевода).

### 7.3 Телефоны и даты
Хранятся нормализованными (`+380…`), показываются единым форматом `+380 97 000 00 01`; даты в часовом поясе пользователя, относительные («сьогодні», «вчора») только при ≤ 7 днях, иначе полная дата.

### 7.4 Доступность
Видимый фокус; все иконки-кнопки с `aria-label`; таблицы с заголовками; управление клавишами в командной палитре и канбане (перемещение карточки клавишами); текст ≥ 12 px, основной 14 px; цель нажатия ≥ 40 px на телефоне.
